# Rulebook / Regelbuch

Tracking: [#1336](https://github.com/n0mad-ai/bastra-recall/issues/1336), under [#1276](https://github.com/n0mad-ai/bastra-recall/issues/1276).

## Contract and implementation status

- A: `rulebook: always` delivers complete bodies within an explicit 8,000-character budget. Overflow names missing rules.
- B: `rulebook: on-demand` delivers a complete description index; overflow uses cursor pagination with catalog hash, total count and end marker. The model loads applicable bodies. Keywords and embeddings never decide membership.
- C: check evidence before mutations on verified hook hosts. Reads remain available. At most two denials per round, then allow and report a violation. Observable outages fail open and are counted. No human input is needed to unblock an autonomous run.

A+B delivery, bounded C checking, category-based action rules and the synthetic multilingual Phase 5 replay are implemented. See the dated host-probe evidence for review findings and limits. Semantic compliance can be checked only where an appropriate validator exists. Hookless clients receive one advisory notice. Answer language remains `language.primary`.

User-directed new rules bind immediately. New agent rule proposals remain separate from the binding catalog and hash. By explicit Owner decision (2026-10-31, #1336), agent changes to existing rules apply directly without a proposal or confirmation, including changes that weaken a rule.

## Sequence

0. Track scope, milestone, labels and rationale (complete).
1. Additive schema and projections, runtime defaults without vault migration (implemented and counter-reviewed).
2. Complete A+B delivery and pagination (implemented and counter-reviewed).
3. Bounded gate, evidence and measured host coverage (implemented; see dated host-probe evidence).
4. Category-based action rules after parity (implemented; uncategorized legacy fallbacks remain).
5. Invented multilingual and unattended-run verification (synthetic replay implemented; no general live-model reliability certification).

Each implementation phase starts with failing tests and ends with green targeted checks, a commit on main and counter-review. No deployment in this task.

## Pattern rationale

Small always-on context plus a description index and model-loaded bodies follows [Claude Code memory](https://code.claude.com/docs/en/memory) and [skills](https://code.claude.com/docs/en/skills), [Cursor rules](https://cursor.com/docs/context/rules), [Kiro steering](https://kiro.dev/docs/steering/) and [Hermes memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory). [Claude Code hooks](https://code.claude.com/docs/en/hooks) supply an action boundary. Explicit overflow makes delivery limits visible; it does not establish semantic compliance.

## Schema stage

Optional fields are `rulebook: always|on-demand`, `applies_when` (a nonblank description in any language) and `rulebook_proposed: {rulebook, applies_when}`. A new declaration sent to save_memory requires the description; loading an older note without it falls back to its summary. Ordinary refreshes preserve these fields.

Runtime defaults require `write_origin: user-directed`, without modifying notes. Within that set, active conventions and floors default to always; user-preference, meta-working and reflex default to on-demand. No other legacy membership is inferred. Explicit declarations take priority. Obsolete and superseded notes are excluded. Session/floor membership is supplied by the caller, never guessed from words. Rulebook catalog and kernel project the daemon’s Vault index. Direct recall/load source validation remains a separate path; the catalog does not reread files in a hook. A summary fallback is marked `applies_when_derived: true` in responses; this marker is not persisted. Mixed direct metadata and `rulebook_proposed` edits are rejected.

New user-directed declarations bind as metadata immediately. Autonomous agent declarations without a user-directed attestation remain separate proposals. Edits to existing rules (body, declaration, applies_when, categories, validator limit/unit/channel/removal, sensitivity, supersession and archive) apply directly, also through MCP edit_memory/save_memory/archive_memory. write_origin is agent-supplied provenance/lifecycle metadata. In save_memory the agent can itself set write_origin:user-directed, which immediately binds a new declaration/validator. Bastra trusts the agent’s attestation that the human dictated the rule; this is an intentional trust boundary, not independently authenticated user-origin evidence. It does not attest approval of an active correspondence task; that still requires the own-user-turn path. Existing-rule status requires a valid declaration already present before the write or a user-directed legacy declaration resolved without session activation/floors. A validator alone never establishes that status. Without a user-directed attestation, an agent adding a validator to a non-rule creates a proposal; a later edit cannot promote that proposal into a binding rule.

This intentionally permits an agent to weaken or retire a rule. The Owner accepted that source-edit risk. Direct CLI/UI/Bash edits are equivalent changes, not a bypass of a source-protection guarantee. No confirmation UI is required for edits; explicit new proposals remain unconfirmed.

## Complete delivery and catalog

The A+B delivery stage runs on startup, resume, clear, compact and fork in the shared Claude Code/Codex session lane. It also serves the existing tool-call re-delivery cadence. Membership comes from explicit declarations and the authorized structural defaults above; no search rank, keyword, language or embedding threshold removes a rule.

`list_rules()` is a read-only tool on search, write and full surfaces. It returns IDs, titles, delivery tiers, scope, descriptions, revisions, `catalog_hash`, `total`, `next_cursor` and `end`. Follow next_cursor until end=true, then use load_memory(id) for relevant bodies. A cursor retains the hook's project scope. If binding content changes between pages, the next result restarts at offset zero with restarted=true and a fresh hash. Proposal fields do not confer membership and are excluded from the binding hash. There is no 40-entry or top-k catalog cap; completeness is tested with 1, 18, 100 and 500 rules.

Always texts are whole, never clipped. The fixed A budget is 8,000 characters including entry headers (approximately 2,000 tokens for Latin text; tokenization varies by language). The B index uses at most 8,000 characters and shares the complete kernel's 9,400-character ceiling; any remainder is explicitly reachable through list_rules(cursor). The full session additionalContext stays below 10,000 characters, including other session sections. When those other sections would push it over the limit, they are deferred as whole sections with a notice; the complete kernel is preserved. These limits describe supported delivery, not a semantic-compliance guarantee.

An always text that is too large or whose current source cannot be read is named as overflow, with the remaining IDs available in the paged catalog. Doctor lists all affected IDs and suggests shortening or changing the tier to on-demand. The hook never claims that every always body was restored when one did not fit.

Both doctor and the context header report the total of possible legacy rules without user confirmation, across servable vault scopes. These candidates remain unbound; no file is rewritten and no confirmation is requested by the hook. A later user-facing review/confirmation command is not implemented in this stage.

The action/Stop check evidence and bounded enforcement contract (C) is implemented with the host limits below. Clients without hooks can read the catalog, but receive advisory guidance rather than guaranteed lifecycle injection or action enforcement.

## Round check and bounded action/Stop control

`rulebook_check({applicable: ["rule-id"]})` records the agent's honest self-report for the current session, context generation and prompt round. `applicable: []` alone is not a decision for correspondence IDs; each such ID must be loaded/declared applicable or explicitly not_applicable with its reason in the current round. It is available on every MCP surface, including search. This is not a complete-catalog protocol or an action-bound proof. Bastra does not classify prompt meaning or validate the applicability judgment. A successful full `load_memory` of a binding rule in this round also supplies evidence for a known caller session; a missing actor ID defaults to main; an explicit lean dismissal, an old load, a stale cached body, a different session or a hint does not. A check without a transport session may supply the exact hook `session_id`; a known transport session takes precedence. A subagent must supply its own `agent_id` to keep its receipt separate. A Claude Code subagent omitting that ID cannot be distinguished from main; these self-reports are not authenticated worker isolation. Codex hook events without agent_id use the main actor of their own session; separate Codex threads have separate sessions. Unmarked, unattributed hook calls cannot inherit a main-thread receipt and retain the bounded fail-open fallback. Explicit worker loads are not main-thread receipts.

The catch-all PreToolUse lane applies C when the scoped rulebook is nonempty. C does not deny known read tools, Bastra's read/check tools or simple syntactically read-only shell commands. Until Phase 4, existing legacy must-load/reflex rules can still interrupt readers under their original finite claim rules. Bastra writing tools now participate, including plugin/canonical server spellings. Unknown MCP schemas, dynamic shell commands and opaque programs cannot be certified read-only; they are treated as potentially mutating, without guessing which rule applies. The effect classifier is a technical allowlist, not a language/intent classifier. It cannot prove the effects of arbitrary executables or shell startup configuration. Existing pending-must-load and action-reflex lanes remain active until Phase 4, including after a successful rulebook check. They remain independent of C's two-attempt round allowance: pending hints interrupt once per booked claim, reflex rules once per rule/session. Exhausting C cannot spend or suppress those claims. A timed-out undelivered denial leaves the legacy claim available. Known reads bypass C catalog work except when periodic context delivery is due. Both old and new reasons are collected in the same call, consuming one C attempt when C also denies.

Before the first potentially mutating action, missing evidence causes at most **two C denials per actor/round**. After that, actions pass and each unchecked observation is audited. A new prompt expires the receipt and resets denial counts; compact/clear/fork creates a fresh context generation. No question, approval or endless retry is introduced. Bastra failure is fail-open. The hook client and daemon spool observable failures locally; the next prompt reports the pending unchecked observations. Counters describe observations and can overlap when a timeout is seen by both client and daemon. Storage failure itself is observable only as far as local storage remains usable.

For every nonempty rulebook, including always-only catalogs, the prompt hook adds a short factual reminder before the answer, including a ready-to-use `rulebook_check` example with its exact `session_id` (and `agent_id` when supplied). Claude Code and version-verified Codex Stop lanes check evidence even for a response with no tools, without interpreting the pasted message. Missing evidence returns `decision: block` **once per actor/round**, asking the model to load/declare applicable rules and explicitly explain every remaining correspondence ID as not_applicable. Structural correspondence includes every validator and explicit correspondence category, without migration or language cues. Further Stops log a violation and continue. The existing independent artifact-validation repair remains in place. Stop continuation does not guarantee that the initial answer was hidden before display. Codex CLI 0.162.1 Stop block/continuation and continue:false precedence are runtime-verified by the local scripted-provider probe. Stop checking is enabled only for that exact Codex version and requires the Stop hook to be installed; Desktop, IDE and other versions remain uncertified. Deferred harvest and save evaluation run exactly once on the continuation. [Runtime observations](rulebook-host-probes.md) distinguish observed boundaries from verified denial; the [host matrix](../packages/daemon/src/host-capabilities.ts) retains per-tool limits.

The checked/deny/unchecked audit rows contain IDs and counters, not prompt or artifact text. The first hookless forwarder context includes an explicit advisory notice. Hooks preserve the source-edit policy above; this stage guarantees checking at covered boundaries, not immutable rule content or semantic compliance.

## Catalog cache and actor attribution

Catalog metadata, rule bodies and byte revisions come from the daemon's in-memory Vault index, as the rule kernel did before Phase 3. There are no hook-side file reads, scan slots, background rebuilds or stale-while-revalidate windows. Parallel sessions share an index view; Vault.on invalidates that view on add/change/remove. Project, floor and active membership and time-based staleness are projected separately for each caller. The IDs-only projection still contains no text/validator/revision metadata and cannot be rendered as a kernel or catalog page. An empty indexed body is valid: its row and revision remain, without a source-unavailable or overflow warning.

The watcher and the existing periodic reconcile keep this index up to date. If a cloud mount misses an event (#199), the catalog can reflect the previous index state until reconcile/reindex succeeds, including privacy or rule changes. It does not promise independent two-second disk validation or immediate detection of an external edit. See the [index freshness boundary](rulebook-host-probes.md#index-source-and-cloud-mount-freshness-boundary-fix-round-7).

The forwarder uses the Claude Code statusline session and ignores inherited `CODEX_THREAD_ID`, which can belong to a launching foreign host. No Codex MCP load-to-session attribution is certified by this adapter: Codex uses `rulebook_check` with the session from the prompt/hook. No Codex `env_vars` forwarding support is assumed. REST transports may carry `x-bastra-agent-id` (main or an explicit worker ID); missing actors default to main for normal loads and checks. Explicit workers stay separate. A missing statusline alone does not establish missing hook support. Other Codex versions remain uncertified. See [probe details and attribution limits](rulebook-host-probes.md).


The action C stage has its own short deadline (150 ms under the default 500 ms gate budget), so catalog errors or slowness do not suppress legacy gates. Undelivered C action reservations are released after timeouts or later gate-write failures, guarded by actor/context/round; recovery still depends on usable state storage. The forwarder's process walk stops at a nearer Codex host instead of borrowing a launching Claude host's feed. See the [primary-source review of Gate versus MCP subagent identity](rulebook-host-probes.md#claude-subagent-identity-gate-versus-mcp-load): hook agent IDs are available, while automatic per-call worker attribution on the shared MCP load connection is not established.

## Structural action categories and transitional correspondence

Rules may declare optional `rule_categories: [github-issues-prs]` or `[correspondence]` (both values are fixed across users; no migration). Categories are metadata, never inferred from titles, `topic_path` or `applies_when`. User-directed categorized rules enter the catalog even with no matching search words. Category changes to existing rules through MCP apply directly, including category removal. Current values are visible in `list_rules` and loads.

The Bash AST identifies GitHub issue/PR mutations, including existing wrapper/API forms. The hook obtains every scoped, nonprivate binding rule of `github-issues-prs` from the in-memory index. **Uncategorized legacy rules keep the previous GitHub query until categorized.** The old query and correspondence cue paths are deliberately retained as a transition; Phase 4 does not yet claim all natural-language matching is gone. Unsupported Codex hosts retain the concrete advisory `Relevant conventions (host cannot gate)` context.

An action-required rule is separate from a round self-report. `rulebook_check({applicable:[]})`, or listing its ID as applicable, cannot fulfill it. Only a successful current full `load_memory` of that exact ID, or `not_applicable:[{id,reason}]` for that exact outstanding ID, discharges it. The exception is audited with its bounded reason, counted as a violation and surfaced in the next prompt. Rules and loads are actor-specific; main loads do not satisfy a worker. Where transport attribution is absent, full loads can supply the exact hook `session_id` and worker `agent_id`; known transport values win. This is self-attribution, not authenticated worker identity. Explicit lean dismissal, cached stale bodies and unrelated sessions do not count. A changed rule revision becomes required again. Requirements survive round checks; action denials share C's cap of two per actor/round, then continue with a violation notice. Existing unrelated legacy claims retain their separate contracts. Failed transport delivery releases its denial reservation.

A model task report can only tighten to `draft-for-review`. It cannot create user approval, replace a user translate-only task, end the task, remove prior validators or repeatedly reset the repair counter. Legacy user-turn transitions remain until a proven language-independent replacement exists. Their DE/EN language limits and quoted-source boundaries remain relevant. Only an approval transition from the user's own, nonquoted turn records `approvalSource:user-turn`; only that provenance renders “the user approved”. Model reports and old unknown-provenance states cannot attest approval or authorize sending.

Every current-round load or applicable declaration of a correspondence validator enables length checking of the answer, independent of activeTask. A short valid answer needs no additional round repair. A model check cannot dismiss or weaken current review/copy task rules, or any rule loaded/declared applicable this round. Attempts are ignored and counted as violations. Outside a current review/copy task, old loads and reflex activation are dismissible with a reason in later rounds. Refreshing indexed validator metadata does not declare it applicable again. A missing receipt requires repair only in approved-copy; review drafts retain structural length checking without a receipt requirement. Answer formatting never creates or approves a task, and model reports cannot clear an existing copy task.

The delivered copy can be fenced with any label, quoted, or plain text. Review/translation prose is not treated as copy; explicit fences (including unclosed ones) and quotes still receive length checks. Approved-copy and no-task responses include remaining prose, preventing short decoy blocks from hiding a long copy. A round repair that originally measured prose as copy retains that prose scope if a later model report starts a review task. A repair raised while checking only explicit draft copy regions does not make unrelated review/translation prose count as copy. Current revisions of declared round validators and loaded/active task validators apply at Stop; valid not_applicable declarations never remove current-round or current review/copy-task validators. There are no task snapshots, timestamp filters or session minima. The production Stop lane refreshes referenced metadata only from the in-memory Vault index; it never opens rule files. User and agent changes apply after watcher/reindex updates, or the documented periodic reconciliation (about 60 seconds) when watcher events are missed. State claims remain bounded and non-queued. MCP edits/overwrites and archive_memory change existing rules directly without rulebook_proposed or confirmation, by Owner decision #1336. This includes validator changes/removal, body, sensitivity and supersession; an indexed obsolete/deleted/archived rule also loses its obligation. write_origin keeps its ordinary provenance meaning. Model rulebook_check self-reports cannot loosen the current indexed validator set, choose channels or grant approval. Model applicability order never selects a channel. A user-selected channel belongs to its task and context generation, and is cleared on a new task/end, compact/clear/generation change, or a new user turn with a different or absent channel candidate. A candidate can select a channel only when its authored recall_when trigger matches splitQuoted(prompt).own through the existing multilingual trigger matcher. A whole-prompt recall hit or a match confined to quoted foreign text does not authorize selection. It narrows only if an eligible current validator for that channel actually exists; otherwise all declared validators apply. Without a user-selected channel, all channels/units apply, with at most two repair requests and one exhaustion. Compact may drop loaded-only rules while the task survives; only active conventions are restored. That delivery boundary is supported, not a guarantee that loaded-only obligations survive compact. Answer labels never choose the channel. Oversized declared copy, or an approved-copy task missing its required receipt, requests validation at most twice before one exhaustion. Adding a model task report cannot reset the current round budget. Codex only records oversized-copy violations and reports them on the next prompt; same-turn length repair remains disabled pending #1311 native evidence. A task receipt does not excuse an oversized copy. Transcript reconstruction still does not prove byte-exact correspondence between a task receipt and later edited copy.

An explicit `not_applicable` decision needs the exact correspondence ID or outstanding action-rule ID and at least ten substantive characters, not punctuation alone. All decisions are audited. Normal correspondence non-applicability is not itself a violation; action-required exceptions retain their visible exception/unchecked treatment. One check can enumerate all IDs or use `not_applicable:[{category:"correspondence",reason:"This round does not prepare correspondence."}]` for every unprotected correspondence ID; current review/copy-task, current-round and concrete action-required rules are excluded from category dismissal. Only an exact `{id,reason}` entry can dismiss a concrete action-required ID. Accepted exception IDs and rejected protected-ID attempts appear in the next prompt, in the configured language. A protected ID does not discard the other valid declarations in that check. Up to 10,000 entries are accepted without the task-active-convention cap when task is omitted.

Task hints are shown only when the catalog contains a validator or correspondence category. All hook metadata remains index-only. Native host coverage is unchanged; supported Stop repair still follows its existing same-turn host/opt-out limits. No new native runtime or live-model semantic certification was added. The existing session capacity of 20 active conventions remains explicit; model tightening exceeding it is rejected without a new check or task transition. See [probe limits](rulebook-host-probes.md).


## Honest guarantee and measured cost

The model decides applicability and can lie. Bastra supplies no semantic second checker and no new prompt-language word lists. It prevents silent omission at the normal Stop boundary: every structural correspondence ID must have an explicit current-round decision, or the bounded passage is audited/reported as unchecked. At most one rulebook Stop block and two action denials remain; failures are fail-open. Telemetry and local storage retain their existing availability/opt-out limits.

The five-language/two-host replay covers 50 harmless rounds (question, calculation, acknowledgement, code, pure translation): one explicit check each, zero additional Stop blocks and zero copy repairs. The 40 deliberately unchecked harmless rounds each get the one allowed Stop block. This is scripted HTTP/adapter cost, not a live-model or LLM-token measurement. Codex length checks produce observations, not a certified native same-turn repair. Rules with validators and explicit correspondence metadata enter this structural category without rewriting the vault; this runtime classification does not grant writer authority to promote an ordinary note.

## Channel-trigger limitation: Japanese inflection

The authored trigger メールを書く does not currently bind email for the own-user text 田中さんにメールを書いてください. ICU tokenizes the inflected verb into short fragments, and the existing conservative phrase/word-form guards do not match it. This follow-up does not add a substring, channel-word or language-specific shortcut. The channel remains unbound and all eligible validators still apply, so a false-positive stricter limit is possible. A general fix needs coordinated short-token/inflection matching and is outside this small proposal-merge fix.

The UserPromptSubmit output shares a 10,000-character budget including the round notice. Optional sections are admitted whole before must-load/delivery bookkeeping. The probe measures both SessionStart and UserPromptSubmit output against this limit.

Pasted content receives neutral provenance guidance: a foreign message requires explanation/application of the correspondence rules through rulebook_check; the user's own instruction is carried out. There is no hook instruction to ask the user to choose a task. Pasted content alone never grants approval. Pending correspondence references can support a later explicit user instruction or a review draft, without claiming that a question was asked.

User-directed legacy memories with validators are existing rules for direct edits and saves even without an explicit rulebook field. A validator on an ordinary non-user-directed memory cannot establish binding rule authority.

Vault-care entries describe pending work; they never authorize deletion. Only the current user turn naming the specific notes authorizes their deletion, without a repeated question for each named note.
