# Graph views and private memories

## English

The user web UI reads `/ui/graph`, `/ui/graph/node?id=…` and `/ui/graph/semantic`. These routes require the existing enabled-UI access boundary: accepted local Host, forwarding token when applicable, and the vault account's OS peer on macOS. The assistant-address gateway checks the browser's account before forwarding. Once a web UI account exists, a valid sign-in session is required on top of this boundary ([Remote access](./REMOTE-ACCESS.md#web-ui-through-your-own-address-sign-in)); the existing OS-account check is macOS-specific. Private memories are included only when that check actually ran and passed; on platforms without it, the UI routes fail closed to the filtered projection.

This user projection includes private memories and documents, their graph edges and full node details, including `related`, `related_via` and body. UI responses use `Cache-Control: no-store`. The external `/api/v1/graph*` projection keeps its existing private filter and REST authorization. Query parameters cannot switch that projection to include private memories. MCP tool sensitivity is unchanged. Semantic caches and in-flight builds are separate for the two projections.

Every graph node carries `sensitivity`: the memory/document's actual value, or `null` for a synthetic ghost/skill with no corresponding memory. `withheld.private` counts actual exclusions. Thus `vault_size - withheld.private` always equals the number of memory and document nodes; the complete UI view has `withheld.private: 0`. Synthetic nodes are not part of that count. The area panel and dashboard area labels also count only memories/documents; raw graph cluster counts retain their existing synthetic references. Semantic positions still require embeddings; date-filtered views count only their selected period.

## Deutsch

Die Nutzer-Weboberfläche liest `/ui/graph`, `/ui/graph/node?id=…` und `/ui/graph/semantic`. Diese Wege verwenden die vorhandene Grenze der eingeschalteten UI: akzeptierter lokaler Host, gegebenenfalls Weiterleitungs-Token und auf macOS das Betriebssystem-Konto des Vaults als Socket-Gegenstelle. Der Assistentenadressen-Gateway prüft das Browserkonto vor dem Weiterleiten. Sobald ein Konto der Weboberfläche existiert, braucht es zusätzlich zu dieser Grenze eine gültige Anmeldesitzung ([Fernzugriff](./REMOTE-ACCESS.md#web-ui-through-your-own-address-sign-in), Englisch); die bestehende Betriebssystem-Kontoprüfung gilt nur für macOS. Private Memories kommen nur mit, wenn diese Prüfung wirklich gelaufen und bestanden ist; auf Plattformen ohne sie liefern die UI-Wege die gefilterte Sicht.

Diese Nutzersicht enthält private Memories und Dokumente, deren Graphkanten und vollständige Knotendetails mit `related`, `related_via` und Body. UI-Antworten tragen `Cache-Control: no-store`. Die externe Sicht `/api/v1/graph*` behält ihren privaten Filter und ihre REST-Zugriffsprüfung. Ein Queryparameter kann private Memories dort nicht einschalten. Die Sensitivity von MCP-Werkzeugen bleibt unverändert. Semantic-Caches und laufende Berechnungen sind für beide Sichten getrennt.

Jeder Graphknoten trägt `sensitivity`: den tatsächlichen Wert der Memory/des Dokuments oder `null` bei synthetischen Ghost-/Skill-Knoten ohne eigene Memory. `withheld.private` zählt die tatsächlich ausgeschlossene Menge. Daher entspricht `vault_size - withheld.private` stets der Anzahl der Memory- und Dokumentknoten; die vollständige UI-Sicht liefert `withheld.private: 0`. Synthetische Knoten zählen dabei nicht mit. Auch Bereichszähler im Bereichspanel und Dashboard zählen nur Memories/Dokumente; die rohen Graph-Clusterzähler behalten ihre bisherigen synthetischen Referenzen. Semantic-Positionen benötigen weiterhin Embeddings; zeitgefilterte Ansichten zählen nur ihren ausgewählten Zeitraum.
