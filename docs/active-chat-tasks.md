# Due tasks in the active chat / Fällige Aufgaben im aktiven Chat

## English

Current main prepares Claude Code chat delivery for v1.2.0. A due task can wake the registered chat in which you last sent a real human message, within `tasks.chatActiveMinutes` (default **30 minutes**). Received task messages, agent turns and system events do not extend that window. Recall does not fall back to an older Claude chat when the most recently used chat is unavailable or unsupported. The board keeps the task; the macOS notification remains an additional channel.

Run the interactive `bastra install` wizard and select Claude Code, or use interactive `bastra tasks setup-hooks` when the task hooks are already configured. Recall asks once whether it may enable `crossSessionInbound: accept` in Claude Code's user settings. **This permits incoming session messages from all programs under your Mac account, not just Recall.** Only an explicit Yes enables it; `--yes`, an existing `accept`, scripted installation or an unanswered prompt does not count. A No is saved and the setup does not ask again. Existing `hold`/`refuse`, unknown inbound settings and managed settings are preserved; chat delivery remains off. New Claude sessions pick up the configured hooks and receiving setting.

Adjust the activity window in the Tasks section of Settings or with `bastra config set tasks.chatActiveMinutes 30` (integer 1–1440). The saved consent is read-only in generic Settings. Changing Claude's receiving setting away from `accept` closes chat delivery immediately; task notifications and the board remain available. No automatic change is made to an existing user's settings during an update.

Recall sends an identified task-data message with an event ID. It never executes text from the task or grants new permission. The private local registration holds the endpoint and token outside the vault. A socket write alone is not a processing receipt or proof that a human read the message. An uncertain delivery is not blindly repeated. Unsupported clients, inactive chats and unknown receiving conditions retain notification and board delivery. The isolated Codex probe succeeded; its product adapter awaits the owner’s build decision in #1425. Global selection covers registered hook clients; programs without an activity hook are not observable and are not covered by this guarantee.

A registration currently lasts 24 hours from SessionStart. With more than 256 retained session records, chat selection closes conservatively. Restart/resume the client for an expired registration; notification and board remain available. Lease renewal and retirement of historical records are tracked in [#1426](https://github.com/n0mad-ai/bastra-recall/issues/1426).

## Deutsch

Das aktuelle main bereitet die Claude-Code-Chat-Zustellung für v1.2.0 vor. Eine fällige Aufgabe kann den registrierten Chat wecken, in dem du zuletzt selbst geschrieben hast, innerhalb von `tasks.chatActiveMinutes` (Standard **30 Minuten**). Empfangene Aufgabenmeldungen, Agentenrunden und Systemereignisse verlängern diese Zeit nicht. Recall weicht nicht auf einen älteren Claude-Chat aus, wenn der zuletzt benutzte Chat nicht erreichbar oder nicht unterstützt ist. Die Aufgabe bleibt auf dem Brett; die Mac-Mitteilung bleibt ein zusätzlicher Kanal.

Starte die interaktive Einrichtung mit `bastra install` und wähle Claude Code, oder verwende bei bereits eingerichteten Aufgaben-Hooks interaktiv `bastra tasks setup-hooks`. Recall fragt einmal, ob es `crossSessionInbound: accept` in Claude Codes Benutzereinstellung aktivieren darf. **Damit werden eingehende Sitzungsnachrichten von allen Programmen unter deinem Mac-Konto zugelassen, nicht nur von Recall.** Erst ein ausdrückliches Ja schaltet es ein; `--yes`, ein vorhandenes `accept`, eine Skriptinstallation oder eine unbeantwortete Frage zählt nicht. Ein Nein wird gespeichert; die Einrichtung fragt nicht erneut. Vorhandenes `hold`/`refuse`, unbekannte Empfangswerte und verwaltete Einstellungen bleiben erhalten; die Chat-Zustellung bleibt aus. Neue Claude-Sitzungen übernehmen die eingerichteten Hooks und die Empfangseinstellung.

Die Aktivitätsgrenze lässt sich im Aufgabenbereich der Einstellungen oder mit `bastra config set tasks.chatActiveMinutes 30` ändern (ganze Zahl 1–1440). Die gespeicherte Einrichtungsantwort ist in den allgemeinen Einstellungen nur lesbar. Wird Claude Codes Empfangseinstellung von `accept` weg geändert, schließt das die Chat-Zustellung sofort; Aufgabenmitteilungen und Brett bleiben verfügbar. Ein Update ändert bestehende Benutzereinstellungen nicht automatisch.

Recall sendet eine gekennzeichnete Aufgabendaten-Meldung mit Ereignis-ID. Es führt keinen Text aus der Aufgabe aus und erteilt keine neue Freigabe. Die private lokale Registrierung hält Endpunkt und Token außerhalb des Vaults. Ein Socket-Schreibvorgang allein ist kein Verarbeitungsbeleg und kein Nachweis menschlichen Lesens. Bei unklarem Empfang wird nicht blind wiederholt. Nicht unterstützte Programme, inaktive Chats und unbekannte Empfangsbedingungen behalten Mitteilung und Brett. Die isolierte Codex-Probe war erfolgreich; ihr Produktadapter wartet in #1425 auf Daniels Bauentscheidung. Die globale Auswahl umfasst registrierte Hook-Clients; Programme ohne Aktivitätshook sind nicht beobachtbar und von dieser Zusicherung nicht erfasst.

Eine Registrierung gilt derzeit 24 Stunden ab SessionStart. Bei mehr als 256 gespeicherten Sitzungseinträgen schließt die Chat-Auswahl konservativ. Eine abgelaufene Registrierung erfordert einen Neustart oder Resume des Clients; Mitteilung und Brett bleiben verfügbar. Verlängerung und Aufräumen historischer Einträge stehen in [#1426](https://github.com/n0mad-ai/bastra-recall/issues/1426).
