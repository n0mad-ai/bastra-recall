# Synthetic convention E2E measurement (#1090)

This probe joins production rule delivery and full loads to actual native CLI
final assistant output on invented tasks. It is a **controlled bridge**: the
controller supplies the production context, loads both fixture rules and makes
the applicability check. It does not measure autonomous rule selection or certify
installed native hooks, native compaction/fork, sending, or arbitrary semantics.
It makes no product-policy changes.

The fixed plan is five tasks × two CLI hosts. `fixtures.mjs` declares the prompts
and independent-assessment rubric before generation. All ten intended attempts
remain in the summary denominator, including blocked, unverified and unstarted
attempts after interruption. A first failed output remains failed even if a later
repair succeeds. Rule revision, host/version, requested model, task/context
generation, exact synthetic output and SHA256 are retained. The model is only
marked confirmed when host evidence establishes it; request configuration alone
is not that evidence. Repeated tasks sharing a context would be clustered, never
independent evidence for a population reliability claim.

The narrow arithmetic oracle checks exact JSON/result/current label. Translation,
draft and approved-copy semantics remain `unverified` until another reviewer
assesses the actual output against the predeclared rubric. Model claims that it
followed the rule do not count. Approved-copy counting uses the exact text payload
inside the fence: the line breaks separating the fence delimiter from its payload
are rendering delimiters, not payload characters. No repair is invented or inferred
from a receipt. A repair needs its own generated bytes, hash and assessment.

Run from the repository root, after core/daemon dependencies are built:

```sh
node --import tsx --import ./scripts/test-env.mjs \
  tools/probes/convention-e2e/run.ts --live-models \
  --copy-codex-auth-from /absolute/path/to/your/codex/auth.json \
  --codex-model gpt-6.1-sol --report /private/tmp/convention-e2e.json
```

The explicit live-model flag acknowledges account-quota use. Use the shared
atomic test lock and `nice -n 15`, start below load 8, and do not run alongside
other builds/tests/evals. The probe itself does not claim a lock or change
priority; the caller owns scheduling. Every CLI request has a 60-second deadline
and SIGTERM/SIGKILL escalation. All client config, vault, settings, logs and hook
state are temporary. No installed hooks or real user vault are read. Codex uses
a new private config root, read-only sandbox, ephemeral sessions, no user config
or execpolicy rules and disabled shell tool/apps. The supplied auth source must
be a regular file. Its temporary copy is mode 0600 under mode-0700 directories
and is removed in `finally`, also after CLI failure. Source credentials are never
modified or printed. Raw provider diagnostics are not exported. The fixture-only
outputs are the actual CLI final bytes.

Claude currently receives a clean config with safe mode, no settings sources,
strict empty MCP, no tools and no persistence. No account credentials are copied
for it; inability to authenticate stays blocked/unknown in the denominator.
Tests use fake output, not real model calls:

```sh
node --import ./scripts/test-env.mjs --test --test-concurrency=2 \
  tools/__tests__/probe-convention-e2e.test.mjs
```

Codex invocation flags were checked against the installed CLI and
[official developer commands](https://learn.chatgpt.com/docs/developer-commands#codex-exec).
This small, deliberately stratified fixture sample is not a 99.9% result, an
error-reduction baseline or a user-population semantic-compliance estimate.
